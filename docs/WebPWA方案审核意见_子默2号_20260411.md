## 二、🔴 重大问题（必须修正）

> [!CAUTION]
> 方案只说了"要做什么"，完全没说"什么时候做完"。

- 备赛计划里明确：**4/18 真实 API 联调上线、4/20 Demo 封板冻结**

- **必须补充**：至少拆为 2-3 个阶段，每个阶段有可验收的产出物和截止日期

**建议拆法：**

| 阶段 | 截止日 | 交付物 | 验收标准 |
|------|--------|--------|----------|
| Phase 1：前端基础升级 | 4/14 | Loading 动画、菜谱卡片 UI、PWA manifest/sw.js | 纯前端 Mock 数据，浏览器打开效果完整 |

### 问题 2：AI 对话接入路径有硬依赖，但未标注风险

> [!WARNING]
> 方案第18行写"接入凯撒的 OpenClaw Daemon API（`/v1/chat/completions`）"，但今天是 4/11，凯撒的 48h Spike 止损点是 4/12 23:59。

- 如果 Spike **失败**（概率不低），这条路就不存在了
- 方案**没有写 Fallback**：Spike 失败后前端对话应该直接对接什么？Coze 的 Web SDK？还是直接调 Coze API？
- **必须补充**：A/B 两条对话接入路径，以及切换条件

**建议：**
```
A 路径（Spike 成功）：app.js → OpenClaw Daemon /v1/chat/completions
B 路径（Spike 失败）：app.js → Coze Chat API / iframe 嵌入扣子 Bot
切换时间点：4/13 00:00 Spike 结果出来后立即决定
```

### 问题 3：前端直接调第三方 API → API Key 暴露

> [!CAUTION]
> `recipe-api.js` 直接从前端浏览器调天行数据 API，意味着 API Key **必须写在前端代码里**。

- 任何人 F12 打开 DevTools 就能看到 Key
- 天行数据虽然不贵，但 Key 被盗刷会超限，Demo 演示时 API 挂掉就尴尬了
- **解决方案有两条，选一条：**
  1. **简易代理**（推荐）：加一个极简 Node/Python 文件做 API 代理（10行代码），Key 放服务端
  2. **接受风险**：如果只是用来评委演示、不公开上线，可以标注"已知风险，可接受"

## 三、🟡 中等问题（建议修正）

### 问题 4：XSS 防护只提了一句

- 方案第22行提到"XSS 防护：对用户输入做转义"
- 但现有代码 `app.js` 第20行直接使用 `innerHTML = text` **没有任何转义**
- 这不是"将来要做"的事，是**现有代码已经有的安全漏洞**
- 建议在方案中明确写出具体做法（如 `textContent` 替代 `innerHTML`，或 `DOMPurify`）

### 问题 5："五行测评"按钮没有任何规划

- 现有 HTML 里有"五行测评"按钮，但方案完全没提怎么处理
- 点了之后什么反应？跳转扣子 Bot 链接？弹出提示？
- **至少写个"待后续迭代"或者给一个临时交互**（如跳转扣子 Bot 的分享链接），否则评委点到是死按钮

### 问题 6：SSE 流式渲染的前提条件不明确

- 方案要求实现"SSE 流式响应、打字机效果"
- 但这取决于后端 API 是否支持 SSE 流式输出
- Coze API 是否支持流式？OpenClaw Daemon 是否实现了？**没有标注**
- 如果后端不支持流式，前端可以做**伪打字机效果**（逐字渲染完整文本），建议写明降级方案

### 问题 7：Verification Plan 太薄

- 只有 6 步手动浏览器测试，没有提到：
  - **弱网/离线测试**（验证 Service Worker 是否真的有效）
  - **多浏览器兼容性**（至少测 Chrome + Safari Mobile）
  - **API 异常场景**（天行数据返回错误/超时时，降级是否触发）
  - **CPS 链接跳转验证**（在微信 WebView 里外卖链接能否正常打开？）

## 四、💡 改进建议（锦上添花）

### 建议 1：加"五行体质上下文"的本地持久化

方案提到菜谱推荐要带"五行体质上下文"，但没说这个上下文从哪来。用户的体质数据存在 Coze Bot 侧，PWA 是独立页面，没有用户登录态。

- **建议**：首次使用时弹出简化版体质选择（3 个问题），结果存 localStorage
- 为什么：评委第一次打开就能体验个性化推荐，不需要先做完整测评

### 建议 2：PWA 图标资源

方案提到 manifest.json 需要图标，但没提图标文件从哪来。

- **提醒**：需要生成至少 192×192 和 512×512 两种尺寸的 PNG 图标
- Apple Touch Icon 也需要 180×180

### 建议 3：加一个"数据追踪桩"为 BP 准备数据

备赛计划和商业计划书都需要"运营数据"。建议在前端加一个极简的事件追踪（console.log 或 localStorage 计数器都行），记录：
- 对话次数
- "今天吃什么"点击次数
- CPS 链接点击次数

评委面前能说出"Demo 上线 X 天，用户触发了 Y 次饮食推荐"，比空谈有力一百倍。
