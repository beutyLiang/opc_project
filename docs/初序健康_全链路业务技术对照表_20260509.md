> 📖 **技术实现详解 · 首次接触**
>
> **活码生成（步骤1）**：每个OPC一个活码，通过企微API生成，`state` 参数里存 OPC-A 的 ID。用户扫码时这个值会原样带回来，是渠道追踪的关键。
> ```python
> # 给 OPC-A 生成专属渠道活码（一次性操作）
> def create_qrcode(opc_id):
>     resp = requests.post(
>         "https://qyapi.weixin.qq.com/cgi-bin/externalcontact/add_contact_way",
>         json={"type": 1, "scene": 2, "state": opc_id, "user": ["xiaoann"]}
>     )
>     return resp.json()["qr_code"]  # 返回活码图片URL给OPC下载
> ```
>
> **回调接收（步骤2）**：用户点"添加"后，**企微主动向你的服务器发 HTTP 请求**（不是你去查，是它推过来）。
> ```python
> @app.post("/wechat/callback")
> async def callback(request: Request):
>     msg = decrypt(await request.body())
>     if msg["Event"] == "add_external_contact":
>         await handle_new_contact(msg["ExternalUserId"], msg["StateId"])
>     return "success"  # 必须立刻返回，否则企微会重复推送
> ```
>
> **绑定+打标签+发欢迎语（步骤3-5）**：三件事在同一个函数里顺序执行。
> ```python
> async def handle_new_contact(user_id, opc_id):
>     await db.execute("INSERT INTO users(wechat_id,opc_id,service_mode) VALUES(:u,:o,'ai')",
>                      {"u": user_id, "o": opc_id})
>     await tag_user(user_id, ["新用户", "待测评"])
>     await send_welcome_msg(user_id, welcome_code)  # welcome_code从回调里拿，10分钟有效
> ```
>
> **关键点**：整个过程中 LangGraph 不参与，这些全是企微标准 API 调用。

> 📖 **技术实现详解 · 日常健康咨询（核心流程）**
>
> **这是整个系统最重要的部分。** 用户发一条消息，背后走6步：
>
> ```
> 用户发消息 → 企微服务器 → 推送到你的服务器（HTTP回调）
>     → FastAPI检查service_mode → 交给LangGraph状态机处理
>     → Agent：①查Mem0记忆 ②查RAG知识库 ③调DeepSeek生成回复
>     → 调企微API把回复发给用户 → 异步把对话存入Mem0
> ```
>
> **消息路由（核心判断）**：
> ```python
> @app.post("/wechat/callback")
> async def callback(request: Request):
>     msg = decrypt(await request.body())
>     user = await db.fetchone("SELECT service_mode FROM users WHERE wechat_id=:u", ...)
>     if user["service_mode"] == "ai":
>         asyncio.create_task(handle_ai_reply(user_id, content))
>     elif user["service_mode"] == "human":
>         await save_chat_history(user_id, "user", content)  # 只存档，不回复
>     return "success"  # 必须立刻返回！
> ```
>
> **LangGraph Agent 内部执行流**：
> ```python
> async def call_agent(user_id, message):
>     memories = memory.search(user_id=user_id, query=message, limit=5)
>     docs = retriever.get_relevant_documents(message)
>     system = f"你是小安。用户信息：{memories}。参考知识：{docs}。合规：不做诊断。"
>     response = await llm.ainvoke([{"role":"system","content":system},
>                                   {"role":"user","content":message}])
>     return response.content
> ```
>
> **消息合并（步骤22）**：3秒内连续消息合并成一条再送 Agent，避免 AI 多次重复回复。
>
> **超时降级（步骤23）**：5秒内 Agent 没返回，先发"让我想想..."，等 Agent 完成后再发正式回复。

> 📖 **技术实现详解 · 产品推荐→购买**
>
> **Tool Calling 是什么**：Agent 在对话中发现需要查产品时，不是自己猜，而是调用你预先定义好的函数去查数据库，再把结果返回给 Agent 决策。
> ```python
> @tool
> def recommend_product(constitution: str, season: str) -> dict:
>     """根据体质和季节推荐产品"""  # 这段注释是给 Agent 看的，它靠这个决定要不要用这个工具
>     return requests.get("/api/product/recommend", params={...}).json()
> ```
>
> **发产品卡片（步骤25）**：AI 生成推荐文案后，消息网关把它包成企微卡片发出去。
> ```python
> requests.post("企微message/send", json={
>     "touser": user_id, "msgtype": "textcard",
>     "textcard": {"title":"疏肝理气茶", "url":"商城链接?uid=xxx&opc=OPC-A"}
> })
> ```
>
> **URL 带参（步骤26-27）**：用户点链接进商城时，URL 里带 uid 和 opc_id，下单时后端就能知道这是谁买的、归哪个 OPC，自动写入订单表并计算佣金。

> 📖 **技术实现详解 · 售后疗程管理**
>
> **定时任务（步骤33,35,37）**：这些不是等用户触发的，是后台每小时自动检查数据库，发现符合条件就主动发消息。用 APScheduler 实现。
> ```python
> @scheduler.scheduled_job('interval', hours=1)
> async def check_followups():
>     orders = await db.fetchall("""
>         SELECT user_id, product_name FROM orders
>         WHERE delivered_at <= NOW() - INTERVAL '3 days'
>           AND followup_sent = FALSE
>     """)
>     for order in orders:
>         reply = await agent.arun(f"用户收到{order['product_name']}3天了，主动问使用感受")
>         await send_proactive_message(order["user_id"], reply)  # v1.3: 检查 48h 窗口，自动选 kf/RPA
>         await db.execute("UPDATE orders SET followup_sent=TRUE ...")
> ```
>
> **主动发消息 vs 被动回复**：主动发消息用 `send_proactive_message`（活跃用户走 kf/send_msg，48h 窗口内最多5条；沉默用户走 RPA 激活）；被动回复（用户先说话）用 kf/send_msg，不限频。

> 📖 **技术实现详解 · 人工介入**
>
> **核心原理**：用户聊天的对象始终是「初序·小安」这个企微账号。AI 回复时通过 API 以小安名义发；真人回复时在企微 App 里手动发，也以小安名义出现。用户**完全看不出区别**。
>
> **切换的技术本质**：数据库里的一个字段 `service_mode`（ai / human / copilot）。消息网关每次收到消息都先查这个字段，决定要不要送给 Agent。
> ```python
> if service_mode == "ai":    → 送给 LangGraph Agent 处理
> if service_mode == "human": → 只存档，不处理，等真人手动回
> if service_mode == "copilot": → Agent 生成草稿，推给真人审核
> ```
>
> **转人工时 AI 自动总结上下文（步骤44）**：真人不需要翻聊天记录，AI 帮他打包好。
> ```python
> summary = await agent.arun(f"总结这段对话给客服看，100字：{recent_chats}")
> # 然后把 summary 推送给真人的企微
> ```

> 📖 **技术实现详解 · OPC 数据查看**
>

> ```sql
> -- MemFire Cloud 配置一次，永久生效
> ALTER TABLE users ENABLE ROW LEVEL SECURITY;
> CREATE POLICY opc_only ON users
>     USING (opc_id = current_setting('app.current_opc_id'));
> ```
>
> **OPC 通过企微登问 AI（步骤60）**：Agent 先查身份，再死切到不同的 Prompt 和工具集。

> identity = await db.fetchone("SELECT 'opc' as role FROM opcs WHERE wechat_id=:u UNION SELECT 'user' FROM users WHERE wechat_id=:u", ...)
> if identity["role"] == "opc":
>     agent = build_agent(system_prompt="你是运营助手...", tools=[query_opc_stats_tool])
