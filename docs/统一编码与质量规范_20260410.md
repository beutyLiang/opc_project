# OPC 大赛：统一编码与质量规范 (2026-04-10)

> **极客精神，强迫症福音**
> 目标：**无论前端语言还是后端语言，不管是谁写的代码，全仓代码看起来必须像同一个人写的。** 任何带有强烈个人随意风格（随意命名、散装函数）的代码，都不允许合入主干（发给评委）。

## 一、 全局强制铁律 (跨语言通用)

1. **唯一命名法 (Naming Conventions)**：
    * **变量与函数（方法）**：前端 JavaScript/TypeScript 一律严格采用 `camelCase`（小驼峰）；后端 Python 一律使用 `snake_case`（蛇形命名）。绝不允许在 JS 里出现 `user_id` 这种风格。
    * **类名 (Classes)**：全量使用 `PascalCase`（大驼峰），如 `UserProfile`。
    * **常量 (Constants)**：全量使用 `UPPER_SNAKE_CASE`，如 `MAX_RETRY_COUNT`。
2. **唯一语言**：代码内所有变量名、函数名与类名**严禁使用拼音**，全英文且要求词性准确（如动词+名词：`getUserData`）。
3. **注释礼仪**：
    * 所有文件的开头，不用写长篇大论的版权，但是复杂的核心类必须用一句话概括这玩意儿干嘛的。
    * 注释只讲 **“为什么 (Why)”** 和 **“坑在哪”**。不要注释“做了什么 (What)”，让代码自己解释自己。
4. **硬编码零容忍**：严禁在业务逻辑中直接写死 URL、API Key 或魔法数字（Magic Numbers）。所有配置项全抽离为 `CONSTANTS` 库或环境变量 `.env`。

## 二、 轨道 B - 前端 (Web PWA) 强约束
* **语言与框架**：TypeScript 优先 + React Hooks / Vanilla 逻辑分离。
* **文件结构**：一个组件一个文件。业务无关的纯 UI 组件放 `components/ui`。
* **排版警察**：全面拥抱 `ESLint` + `Prettier`。
* **样式纪律**：CSS 不允许写散装 `style="color:red"`。采用全局变量控制（CSS Variables），设计系统化。

## 三、 轨道 A - 后端 (OpenClaw Spike) 强约束
* **代码格式化**：全线应用 `Black` 和 `Ruff`。哪怕是 Spike，发出来的代码也必须对齐（每行限宽 88 字符）。
* **类型提示 (Type Hints)**：既然用了 Python，所有函数入参必须加 Type Hint（例如 `def process_data(user_id: str) -> dict:`）。
* **错误兜底**：禁止随便打印 `print` 报错，重要日志一律走标准化 Log，捕捉最细颗粒度的异常。
