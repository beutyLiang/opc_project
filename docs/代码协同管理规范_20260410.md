# OPC 大赛：代码协同与双轨隔离规范 (2026-04-10)

> **制定者**：子默 (Zimo) | **联合执行**：凯撒 (Caesar)
> **目的**：在极短的10天冲刺期内，保证双线开发互不干扰，随时能无痛合码或剥离废弃代码。

## 一、 整体结构：隔离型 Monorepo

我们将在 `opc-project/` 根目录初始化一个整体的 Git 仓库，所有人在此仓内进行提交。但目录必须严格隔离：

```text
opc-project/
│
├── frontend/                <-- 【子默领地】Web PWA 核心前端代码区（React/Vite）。
│   ├── src/
│   ├── package.json
│   └── .eslintrc.cjs        <-- 严格的前端代码规范与 Linter
│
├── spikes/                  <-- 【凯撒领地】激进技术与探索区。
│   └── openclaw-daemon/     <-- A轨道的 48小时 Spike 项目代码请全部放入此处！如果失败，直接整库移除，不影响主线。
│
├── docs/                    <-- 文档、方案、UI资产与架构图。
│
└── .gitignore               <-- 全局屏蔽环境配置、虚拟目录和日志。
```

## 二、 协同底牌（铁律三条）

**第一条：【严禁跨界污染】**
- 凯撒进行 OpenClaw 开发时，所有的 `.py`、依赖、配置和 Dockerfile 只能出现在 `spikes/openclaw-daemon/` 内部。
- 绝不允许将测试用的服务端脚本写到根目录下。

**第二条：【明确的接口契约】**
- 不要过度设计 API。在凯撒 48h 链路跑通前，前端 `frontend/` 会自行撰写 Mock JSON 数据打通页面。
- 如果 Spike 成功，凯撒需要在 `spikes/` 里提供明确的 `swagger` 或 `README` 来告知子默怎么获取 Agent 数据。

**第三条：【一日一清】**
- 虽然在同一个 Git 仓库，但为避开冲突，大家每天完工后至少推一份 Commit 并写清楚变动范围。
- 若需修改对方目录代码，必须先过口头（Agent Bridge）审核。

## 三、 凯撒确认流程
阅读完本规范后，如果接受该物理文件夹隔离设计，请凯撒立刻回复明确确认。一旦定下，马上在主目录 `git init` 进入实质性编码测试。
