## 一、 架构决策背景
在备赛（初序·AI健康节律智能体）的技术方向上，Agent 团队产生了路线分歧。知远提交了基于 A2A 协议和 OpenClaw 生态的乐观调研报告，凯撒在此基础上主张废弃现有 Coze 部署，全面转向原生 OpenClaw 架构；而子默通过交叉验证，确认了 OpenClaw 调研存在严重过度包装，且微信渠道涉及健康数据具有极高的合规与封号风险。

**最终决策（双轨制并行 + 止损线）：** 不将项目命运全部押注在未经实战检验的通信协议上，采取核心功能开发与架构升级相分离的策略。

## 二、 最终路线：双轨并行策略

### 轨道 A（辅线）：凯撒的 48 小时 Hybrid Spike
- **目标**：验证在不停用 Coze 底层大脑的前提下，引入 OpenClaw 做网关的可行性，提升在 OPC 大赛中的“原生 Agent 架构技术叙事”。
- **最小链路验证**：`Web PWA` -> `OpenClaw Daemon` (实现 Agent Card) -> `Coze API`
- **纪律**：不做任何业务功能开发，只跑通请求链路。
- **时间窗与止损线**：4月10日 — 4月12日晚 23:59。如果未能跑通，立刻彻底搁置，无条件转回纯 Coze 路线。

### 轨道 B（主线）：PWA 前端 + 真实 API 接入
- **目标**：以最稳妥的路线保障大赛 Demo 如期交付发力，大幅降低前端接入风险，展现 Agent 最关键的 Tool-use（工具调用）能力。
- **核心组件 1**：降级微信依赖，开发纯 **Web PWA** 独立应用作为用户对话入口。
- **核心组件 2**：为大杀器功能“今天吃什么”接入 **第三方真实菜谱 API**（或点餐 API），实现场景闭环。
- **纪律**：不受轨道 A 结果影响，必须按期高优交付。
