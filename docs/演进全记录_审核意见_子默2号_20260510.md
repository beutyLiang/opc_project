## 一、🔴 遗漏：RPA 与 FastAPI 通信机制写错了

**第 346 行**：

> "RPA 模块是独立组件，运行在 Windows Server 上，与 FastAPI 后端通过**消息队列**通信"

**问题**：三文档中从未定义过消息队列。技术说明书里写的 `send_proactive_message` 是直接调 `rpa_send_via_kf_console()`，这是同步调用，不是消息队列模式。

如果告诉凯撒"走消息队列"，他会去搭 Redis/RabbitMQ 等消息队列基础设施，但这是未规划的依赖。

**修订要求**：
- 方案 A（当前设计）：RPA 是本地脚本，FastAPI 通过异步任务或 DB 任务表触发，不引入消息队列
- 方案 B（未来演进）：引入消息队列（Redis Streams 等）实现解耦，但这是 Phase 2+ 的事

建议改为：
> "RPA 模块是独立组件，运行在 Windows Server 上。**Phase 0-1：FastAPI 通过数据库任务队列（`rpa_queue` 表）调度 RPA**；Phase 2 以后视规模决定是否引入消息中间件（Redis Streams）。"

## 二、🔴 遗漏：`send_proactive_message` 代码存在逻辑 Bug

**第 297-311 行**，当前代码：

```python
if silent_hours < 48:
    resp = requests.post(...)
    if resp.json().get("errcode") == 0:
        return {"status": "sent", "channel": "kf"}

# 沉默用户：RPA 激活
if user["activation_count"] < 3:
    await rpa_send_via_kf_console(user_id, activation_msg)
    return {"status": "queued", "channel": "rpa"}

return {"status": "failed", "reason": "user_dormant"}
```

**Bug 1**：活跃用户 kf 发送失败（errcode ≠ 0）时，代码**不会 return**，会继续往下走到 RPA 分支——一个本来在 48h 窗口内的活跃用户，kf 发送失败后反而触发了 RPA 激活，逻辑错误。

**Bug 2**：`activation_msg` 变量未定义，应该是根据 `user["activation_count"]` 查数组拿的：
```python
ACTIVATION_MESSAGES = [
    "小安这边关心一下你，这几天感觉怎么样呀？",
    "好久没聊了，最近有没有按时吃药呢？",
    "小安一直在这里，有需要随时找我哦~"
]
activation_msg = ACTIVATION_MESSAGES[user["activation_count"]]
```

**修订要求（完整修正版）**：
```python
async def send_proactive_message(user_id: str, content: str) -> dict:
    user = await db.fetchrow("SELECT * FROM users WHERE user_id = :uid", {"uid": user_id})
    silent_hours = (datetime.now() - user["last_message_at"]).total_seconds() / 3600

    if silent_hours < 48:
        # 活跃用户：kf API 直接发
        resp = requests.post(f".../kf/send_msg?access_token={token}", json={
            "touser": user_id, "open_kfid": KF_ACCOUNT_ID,
            "msgtype": "text", "text": {"content": content}
        })
        if resp.json().get("errcode") == 0:
            return {"status": "sent", "channel": "kf"}
        else:
            return {"status": "failed", "reason": "kf_api_error",
                    "errcode": resp.json().get("errcode")}
            # ← 不继续走 RPA，kf 失败是系统错误，需告警

    # 沉默用户（> 48h）：走 RPA 激活
    if user["status"] == "dormant":
        return {"status": "failed", "reason": "user_dormant"}

    if user["activation_count"] < 3:
        activation_msg = ACTIVATION_MESSAGES[user["activation_count"]]
        await add_to_rpa_queue(user_id, activation_msg)  # 写入 rpa_queue 表
        return {"status": "queued", "channel": "rpa"}

    # activation_count >= 3，标记休眠
    await db.execute("UPDATE users SET status='dormant' WHERE user_id=:uid", {"uid": user_id})
    return {"status": "failed", "reason": "user_dormant"}
```
