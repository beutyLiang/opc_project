## 一、关键判断：这个比赛考什么？

> [!IMPORTANT]
> **这不是一个算法竞赛，这是一个 AI 创新应用的入孵选拔。**

知远之前给的 VRPTW 路径规划拆解很专业，但我仔细核对了赛事信息后发现：

| 维度 | 知远的拆解（物流算法赛） | 实际赛道（OPC创新应用赛） |
|------|:---:|:---:|
| 评审标准 | 算法效率 + 最优解 | **产品创新 × 用户体验 × 市场潜力** |
| 参赛流程 | 提交代码跑分 | **演示视频 → Demo → 路演答辩** |
| 面向人群 | 算法工程师 | **龙头企业技术人员、创业者、超级个体** |
| 目标 | 竞赛排名 | **入孵 OPC 社区（工位+资金+算力）** |

**子默结论**：知远的 VRPTW 技术拆解可以作为**储备知识**（万一评委问物流优化场景），但我们的核心战场不在算法跑分，而在于：**展示初序作为一个 AI 健康管理产品的创新性和市场潜力。**

---

## 二、我们的核心打法：「三层蛋糕」策略

```
┌─────────────────────────────────────────────┐
│  第三层：技术护城河（A2A + 架构先进性）    │  ← 技术加分
├─────────────────────────────────────────────┤
│  第二层：产品体验（Demo 惊艳 + 用户故事）  │  ← 核心得分
├─────────────────────────────────────────────┤
│  第一层：市场故事（大健康 × 中医 AI 蓝海）  │  ← 基础得分
└─────────────────────────────────────────────┘
```

### 第一层：市场故事（拿基础分）

- **10 万亿大健康市场 × 3 亿中医养生用户 × 无同类 AI 竞品** = 巨大蓝海
- **一人公司范式 = OPC 赛道的完美匹配**（一个 CEO + AI 团队矩阵）
- **海珠区本地创业者** = 政策扶持优先级

### 第二层：产品体验（拿核心分）

这是决胜的关键。评委要看到一个**可用、好用、想继续用**的产品。

| 功能模块 | 目标体验 | 当前状态 | 优先级 |
|----------|---------|:------:|:-----:|
| 五行体质测评 | 3分钟完成，结果专业又易懂 | ✅ 已上线 | — |
| "今天吃什么" | 每日打开的理由（高频触发） | ❌ 未完成 | 🔴 P0 |
| 节律提醒 | 根据时令+体质推送建议 | ❌ 未完成 | 🟡 P1 |
| 打卡/成就系统 | Hooked 模型的可变酬赏 | ❌ 未完成 | 🟡 P1 |
| 舌诊拍照 | 视频演示的"Wow Moment" | ❌ 未完成 | 🟠 P2 |

> [!TIP]
> **「今天吃什么」是唯一一个能让评委产生"我也想用"的功能。** 这是 P0 中的 P0。

### 第三层：技术护城河（拿加分）

这里整合知远的两份调研：

**A2A 协议接入（加分，非必须）**
- 展示「初序」不是一个孤立 Bot，而是可以通过 A2A 协议与其他 Agent 互操作的"超级调度者"
- 落地形式：在路演中**现场演示**初序通过 A2A 调用一个营养数据 Agent
- 前提：需要从 Coze 迁出独立部署

**OpenClaw 微信入口（高价值，建议做）**
- 展示「初序」可直接以微信好友形态触达用户 = **极低获客成本**
- 落地形式：演示视频中展示"扫码加好友 → 直接开聊"
- 风险：腾讯云 Lighthouse 部署需测试稳定性

## 五、对知远 VRPTW 拆解的处置意见

> 知远的技术拆解质量很高，但方向对错了赛道。

**处置方式：**
1. **归档保留**：VRPTW 技术拆解存入 `docs/research/` 作为技术储备
2. **路演 Q&A 预案**：如果评委问"你们能做物流场景吗？"，可以直接拿出这套分析展示技术功底
3. **不投入开发资源**：不要在路径规划算法上花时间，那不是评审标准

> [!NOTE]
> **知远后续可以重新聚焦到以下调研方向**：
> - 竞品分析：市面上有没有类似的中医 AI Agent？
> - 用户数据：中医养生用户的痛点调研 / 第三方报告
> - 政策利好：海珠区 / 广州市对大健康 + AI 的扶持政策
