# API选型报告：“今天吃什么”功能闭环 (2026-04-10)

> 前置 4 问思考（Zoey 规则十一）：
> 1. **她是谁**：25-35岁、工作忙碌、懂生活但没时间、有轻度亚健康/节律失调的职场女性（点外卖高频人群）。
> 2. **她此刻的痛**：每到饭点就纠结“吃什么外卖才健康/不违背五行调养”，或者“想自己做但不知道怎么做快手菜”。
> 3. **她凭什么停下来**：当我们准确说出她“今天中午最该吃什么”（基于五行体质+时令）时。
> 4. **她为什么一定会行动**：我们不但给建议，还直接给了“菜谱做法”或“外卖直接点单链接（带红包）”，省时省力。

---

## 选型背景：真实世界的数据墙
我们需要通过真实 API 展示 Agent 的 Tool-use（工具调用）能力。但在实际对接中存在一道“数据墙”：
美团 / 饿了么的**核心外卖订单下发 API** 严格限制，只对实名认证的网点企业/大型餐饮连锁开放。个人开发者（或初创未受认证阶段）**无法直接通过 API 让用户完成支付点餐闭环**。

因此，我们的选型策略必须分为“菜谱侧（给做法）”和“外卖侧（给优惠及跳转）”。

## 一、 菜谱 API 选型（教你怎么做）

| 平台 | 特点 | 针对开发者的友好度 | 商用与价格初步估计 | 建议 |
|------|------|--------------------|-------------------|------|
| **天行数据 (TianAPI)** | 接口极简，JSON 结构非常适合 LLM 直接读取。 | 极高（很多个人小工具在用） | 免费配额低；升级为高级会员几十元一年。 | **首选测试**。极其适合 Demo 极速开发，代码对接成本最低。 |
| **聚合数据 (Juhe.cn)** | 老牌机构，菜谱收录极全，含有分类和营养数据。 | 高（文档详尽） | 超出免费后按次计费或购买包年套餐，且商用需过审。 | 备选。如果天行的返回图片等质量不够，随时切到他们家。 |

## 二、 外卖 API 替代方案（让你直接点）

既然没有美团开放平台的订单级直接 API，我们要展示能力，可以使用 **“外卖 CPS（淘宝客/推客）分销接口”**。

- **这是什么**：对接美团外卖推客 / 饿了么联盟 API。
- **用户视角**：Bot 说“你今天肝火旺，中午适合吃苦瓜炒肉，我已经帮你找好了美团大红包，👉点这里领券下单”。
- **开发难度**：门槛极低，个人可注册。获取专属推广链接即可。
- **附带收益**：不仅闭合了功能体验测试，如果别人真的从你这个 PWA/Bot 里领券点外卖了，项目还能**赚到外卖返佣的钱**。这就构成了我们 OPC 项目向评委讲的“可持续商业变现路径”的第二环（除了付费报告之外的外卖佣金引流）。

## 三、 结论建议（子默的技术决断）

为了在 4/20 前交付惊艳评委的 Demo，我们的 Tool-use 采用以下组合：
1. **内容输出端**：用 **天行数据（TianAPI）** 获取真实的高清菜谱、用料数据，组装进我们的 AI 返回卡片中。
2. **行动号召端**：在前端 PWA 加入基于 **外卖 CPS** 的一键跳转优惠链接。
