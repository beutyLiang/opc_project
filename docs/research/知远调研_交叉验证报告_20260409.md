### ⚠️ 需要修正

| 声明 | 问题 | 正确信息 |
|------|------|----------|
| 端点路径 `/.well-known/agent.json` | ⚠️ **路径名称微偏** | 规范中是 `/.well-known/agent.json`，但部分文档写作 `agent-card.json`。知远写的版本恰好是对的。 |
| "A2A 是由 Linux Foundation 托管的开放标准" | ⚠️ **省略了关键历史** | A2A 是 **Google 发起**（2025.04），后捐赠给 Linux Foundation（2025.06）。报告写法可能让人误以为是 LF 原创。 |

### 💡 报告遗漏

- **未提 A2A 与 MCP 的互补关系**：A2A 管 Agent-to-Agent，MCP 管 Agent-to-Tool，两者互补。这对初序技术架构选型有指导意义。
- **未提前置条件的难度**：报告最后说"前提是Bot需从Coze迁出独立部署"，但没有评估迁出的工作量和技术挑战。

### 🔴 重大错误

| 声明 | 问题 | 正确信息 |
|------|------|----------|
| "OpenClaw 1.0 稳定版" | 🔴 **不存在这个版本号** | OpenClaw 是一个持续迭代的开源项目（前身 Clawdbot → Moltbot → OpenClaw），**没有官方 "1.0 稳定版"** 发布。 |
| "超 150 家组织支持" | 🔴 **数据张冠李戴** | **150+ 组织支持的是 A2A 协议**，不是 OpenClaw。OpenClaw 的成就是 **10万+ GitHub Stars**。知远把两份调研的数据搞混了。 |
| "成为OPC的首选底层" | 🔴 **缺乏依据** | 无权威来源证实 OpenClaw 是 OPC 的"首选底层"。这是知远的主观推测，被包装成了事实陈述。 |
| "OpenClaw 协议" | 🔴 **概念混淆** | OpenClaw **不是协议**，它是一个**开源 Agent 平台/框架**。知远在报告中多次将其称为"协议"，与 MCP、A2A 等真正的协议混淆。 |

### ⚠️ 需要补充

| 遗漏 | 重要性 |
|------|--------|
| **OpenClaw 的安全风险** | 🔴 高 — 研究人员已警告恶意第三方 Skills（插件）风险，部分组织限制使用。**健康数据场景尤需注意** |
| **ClawBot 仅限个人单聊** | ⚠️ 中 — 不支持群聊，不支持自动操作微信隐私数据。影响"B端渗透"策略的可行性 |
| **OpenClaw 创始人已加入 OpenAI** | ⚠️ 中 — 项目已转为独立开源基金会运营，长期维护性需评估 |
| **企业微信"MCP能力"** | ⚠️ 中 — 报告提到"企业微信的MCP能力"但未给出具体来源或证据 |

## 🎯 综合建议

### 对初序 OPC 备赛的影响

1. **A2A 方向：值得推进** — 事实基本可靠，技术叙事有力。建议在演示中展示 A2A Agent Card 发现机制。
2. **ClawBot 微信入口：方向正确但需谨慎** — 核心功能真实存在，但知远的包装过度乐观。需要：
   - 实际测试 ClawBot 部署流程
   - 评估健康数据在微信通道中的合规风险
   - 确认是否满足 OPC 参赛 Demo 的需求
