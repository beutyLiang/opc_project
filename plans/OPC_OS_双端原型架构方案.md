# OPC OS 双端原型架构方案

> **目标**：将现有的单一管理后台，升级为「Boss 端 + C 端」双端架构，让飞轮六环节从"画饼"变成"可点击的真实交互"。
> **原则**：纯前端原型（HTML/CSS/JS），通过 localStorage 实现双端数据联动，零后端依赖。

---

## 一、架构全景

```
                          ┌──────────────────────────────────────┐
                          │         OPC OS · Boss 端              │
                          │      （CEO / 管理者视角）              │
                          │                                      │
                          │  📊 驾驶舱    🏢 组织架构   📋 任务中心 │
                          │  🤖 Agent管理  💰 财务中心             │
                          │                                      │
                          │  ── 以下为新增/重构 ──                 │
                          │  📡 用户运营    📣 营销中心             │
                          │  📱 C端预览（iframe 嵌入手机框）        │
                          │                                      │
                          └───────────────┬──────────────────────┘
                                          │
                                  localStorage 数据桥
                                          │
                          ┌───────────────┴──────────────────────┐
                          │      初序健康 · C 端（用户端）         │
                          │      （消费者视角，独立入口）          │
                          │                                      │
                          │  🏠 首页/落地页                       │
                          │  💚 AI 健康管家（体质测评 + AI 对话）  │
                          │  📋 体质报告页                        │
                          │  🛒 健康商城（基于体质推荐）           │
                          │  👤 个人中心（档案 + 订单 + 邀请）     │
                          │  🎁 裂变分享页                        │
                          │                                      │
                          └──────────────────────────────────────┘
```

**为什么是两个端而不是三个、四个？**

- Boss 端 = CEO 管理一切的地方。飞轮中的"人群筛选、社群运营、精准营销"本质是**运营决策**，属于管理后台的数据面板，不需要独立产品。
- C 端 = 用户接触的所有东西。飞轮中的"AI 客服接待、复购裂变"是**用户侧行为**，必须有独立入口。
- 企微对话只是 C 端的一个触点（渠道），在原型阶段用 C 端内嵌的 AI 对话框模拟即可，不需要单独做一个端。

### 2.2 新页面设计

#### 📡 用户运营（替代原"AI 健康管家"位置）

**定位**：CEO 视角看用户数据，对应飞轮的"人群筛选"环节。

操作步骤（用户浏览此页面的体验）：
1. 顶部：三个统计卡片 — 今日新增用户 / 完成测评人数 / 用户留存率
2. 左侧大卡片：**用户画像分布** — 饼图展示各体质类型的用户比例（阳虚 35%、气虚 22%、湿热 18%...）
3. 右侧上卡片：**渠道来源** — 条形图展示各引流渠道的用户数（小红书 45%、抖音 30%、视频号 15%、直接访问 10%）
4. 右侧下卡片：**用户标签分布** — 标签云展示高频标签（高意向、价格敏感、复购客、沉默用户...）
5. 底部：**用户列表** — 表格显示最近注册的用户（昵称、体质类型、来源渠道、标签、测评时间）

#### 📣 营销中心（替代原"健康商城"位置）

**定位**：CEO 配置营销策略，对应飞轮的"精准营销 + 复购裂变"环节。

操作步骤：
1. 顶部：三个统计卡片 — 活跃营销活动数 / 本月发放优惠券 / 裂变新增用户
2. 卡片一：**SOP 自动化任务** — 表格展示当前运行的自动化规则
   - 示例行："新用户欢迎 → 加好友后 1 小时 → 推送体质测评链接 → 执行中 ✅"
   - 示例行："沉默唤醒 → 7 天未互动 → 推送节气养生提醒 → 执行中 ✅"
   - 示例行："复购触达 → 上次购买 30 天 → 推送同体质新品 → 执行中 ✅"
3. 卡片二：**裂变活动管理** — 当前活动列表
   - "邀请好友测体质" — 参与人数 87 / 带来新用户 34 / 转化率 39%
   - "春季养肝茶拼团" — 参与人数 42 / 成团 18 / GMV ¥680
4. 卡片三：**推送任务** — 给不同标签的用户推不同内容
   - 表格：标签筛选 → 推送内容 → 预计覆盖人数 → 状态
   - 按钮："+ 创建推送"（点击弹出配置弹窗）

#### 📱 C 端预览（新增）

**定位**：在 Boss 端内，用一个手机外框 iframe 嵌入 C 端页面，CEO 可以实时预览用户看到的界面。

操作步骤：
1. 页面中央放一个 iPhone 外框（CSS 画的手机壳）
2. 内部是一个 `<iframe>` 指向 `../user_app/index.html`
3. 左侧放一组快捷跳转按钮：首页 / 测评 / 商城 / 个人中心
4. 右侧显示实时数据：当前在线用户数、今日访问量
5. 底部放一个"在新窗口打开"的链接

## 三、C 端新建（独立 H5 应用）

### 3.1 技术方案

- 路径：`opc_demo/user_app/index.html`（独立 SPA，与 Boss 端完全分离）
- 设计风格：**移动端优先**，宽度固定 375px 居中显示（或响应式适配）
- 色调：从 Boss 端的暗黑科技风 → 转为温暖、亲和的浅色系/渐变绿（健康感）
- 数据来源：读写 `localStorage`，与 Boss 端共享同一份 `opc_state`

### 3.2 页面详细设计

#### 🏠 首页 / 落地页

**定位**：用户第一次接触初序健康时看到的页面，核心目标是引导用户去做体质测评。

用户操作步骤：
1. 打开页面 → 看到品牌 Logo + 标语"了解体质，吃对食物"
2. 主视觉区域：一个大的 CTA 按钮 **"3 分钟测出你的体质 →"**
3. 下方滚动展示：
   - 三个卖点图标卡片（"AI 精准分析" / "个性化方案" / "持续追踪"）
   - 用户评价轮播（模拟 3 条好评）
   - 底部 tab 导航栏：首页 / 测评 / 商城 / 我的

#### 💚 AI 健康管家 / 体质测评页

**定位**：核心功能页。用户在这里完成体质测评、获取 AI 建议。对应飞轮"AI 客服接待"。

用户操作步骤：
1. 点击"开始测评" → 进入对话式测评界面
2. AI 依次提问 5 个问题（年龄段 → 睡眠 → 饮食偏好 → 情绪 → 身体症状）
3. 每个问题以**选择题卡片**的形式呈现（点击选项而非打字）
4. 5 题答完 → 显示"正在分析..."动画（3 秒）
5. 跳转到**体质报告页**
6. 报告页底部：两个 CTA 按钮
   - "查看推荐产品 →" → 跳转商城（已按体质筛选）
   - "加入健康社群 →" → 显示企微二维码弹窗（模拟加企微）
7. 测评完成后，数据写入 localStorage → Boss 端"用户运营"页面的统计数字自动 +1

#### 📋 体质报告页

**定位**：展示测评结果，建立信任感，引导转化。

用户操作步骤：
1. 顶部：体质类型大标题 + 五行元素图标（如"木型体质 · 🌿"）
2. 雷达图：五维评分（肝/心/脾/肺/肾）
3. 体质解读：2-3 段简短描述（这种体质的特征、易发问题）
4. 调养建议：四宫格卡片（饮食 / 作息 / 运动 / 情绪）
5. 推荐产品：3 个与体质匹配的产品卡片（从商城数据中筛选）
6. 底部：分享按钮 "分享给朋友，一起测体质" → 跳转裂变页

#### 🛒 健康商城

**定位**：用户侧的购物页面。与 Boss 端"健康商城"共享相同的产品数据，但 UI 完全不同。

用户操作步骤：
1. 顶部：搜索栏 + 体质筛选标签（"适合我的" / "全部" / "节气推荐"）
2. "适合我的"默认选中 → 根据用户已测的体质类型过滤产品
3. 产品列表：竖版瀑布流卡片（图片 + 名称 + 价格 + "适合XX体质"标签）
4. 点击产品 → 弹出产品详情弹窗（图片、描述、价格、"立即购买"按钮）
5. 点击"立即购买" → 显示 toast "已加入购物车" / 跳转模拟支付成功页
6. 购买完成 → Boss 端驾驶舱的营收数字更新

#### 👤 个人中心

**定位**：用户查看自己的数据、管理账户。

用户操作步骤：
1. 顶部：用户头像（默认头像）+ 昵称 + 体质类型标签
2. 我的体质档案 → 点击跳转体质报告页
3. 我的订单 → 显示历史订单列表（模拟数据）
4. 邀请好友 → 跳转裂变分享页
5. 联系客服 → 弹出企微二维码

#### 🎁 裂变分享页

**定位**：用户分享给朋友的落地页。对应飞轮"复购裂变"。

用户操作步骤：
1. 展示内容："你的好友 XXX 邀请你测体质，双方各得 ¥5 优惠券"
2. 大按钮："免费测我的体质 →" → 跳转测评页
3. 底部：活动规则说明
4. 新用户完成测评后 → localStorage 记录裂变来源 → Boss 端"营销中心"裂变数据 +1

## 四、双端数据联动方案

Boss 端和 C 端共享同一个浏览器的 localStorage，通过约定的 key 命名空间实现数据桥接。

### 4.1 共享数据结构

```javascript
// localStorage key: 'opc_shared_data'
{
  // C 端写入 → Boss 端读取
  users: [
    {
      id: 'u001',
      nickname: '小雨',
      bodyType: '木型体质',
      channel: '小红书',        // 渠道来源
      tags: ['高意向', '已测评'],
      assessmentDate: '2026-04-24',
      orders: []
    }
  ],
  assessmentCount: 347,         // 总测评完成数
  todayNewUsers: 12,            // 今日新增
  referralCount: 34,            // 裂变带来的用户数

  // Boss 端写入 → C 端读取
  activePromotions: [           // 当前活动
    { title: '邀请好友测体质', reward: '¥5优惠券', active: true }
  ],
  sopTasks: [                   // SOP 自动化任务
    { trigger: '新用户加好友', delay: '1小时', action: '推送测评链接', status: 'running' }
  ]
}
```

### 4.2 联动场景

| 用户在 C 端的操作 | Boss 端的变化 |
|-----------------|--------------|
| 完成体质测评 | 用户运营 → 测评人数 +1，用户列表新增一行，画像饼图更新 |
| 购买商品 | 驾驶舱 → 营收数字增加，财务中心 → 订单记录新增 |
| 通过分享链接注册 | 营销中心 → 裂变数据 +1，活动参与人数更新 |
| 点击"加入社群" | 社群管理 → 社群人数 +1 |

实现方式：Boss 端使用 `storage` 事件监听 + 轮询读取，无需 WebSocket。

## 七、路演时的演示策略

有了双端之后，路演策略应该升级为**双屏演示**：

1. **左屏（Boss 端）**：投影仪/大屏展示 OPC OS 管理后台
2. **右屏（C 端）**：用手机或第二个浏览器窗口展示用户端

**演示脚本调整**：
1. 开场：Boss 端驾驶舱，展示经营数据
2. 切到 C 端：模拟一个用户做体质测评 → 看到报告 → 购买产品
3. 切回 Boss 端：驾驶舱数据实时更新（用户+1、营收+¥39.9）
4. Boss 端任务中心：给 Agent 派发任务
5. Boss 端营销中心：展示 SOP 自动化和裂变数据
6. C 端裂变页：展示"邀请好友"的用户侧体验
7. 收尾：双屏同框，"一个人 + N 个 AI = 一家完整运转的公司"

这种"C 端操作一下 → Boss 端立刻有反应"的联动效果，比单屏演示的冲击力强很多。

## 八、风险与约束

| 风险 | 缓解措施 |
|------|---------|
| C 端 UI 品质不够高 | 参考市面上成熟的健康类 App（薄荷健康、丁香医生）的设计语言 |
| 双端联动延迟 | localStorage 是同步的，同一浏览器内无延迟；跨浏览器不通，路演时统一用 Chrome |
| 开发量偏大 | Phase 1 的核心闭环 5 个任务优先做完，Phase 2/3 可根据路演时间取舍 |
| Coze AI 接入 | C 端测评先用预设逻辑，AI 对话作为增强功能放在 Phase 3 |
